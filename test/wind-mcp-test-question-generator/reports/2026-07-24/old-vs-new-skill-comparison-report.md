## 2. 总体结论

新版本不是简单更新工具描述，而是对契约组织、公共参数、CLI 校验、错误处理和结果安全进行了一次系统性重构。

目录差异统计为 29 个差异文件、约 1724 行新增、1608 行删除。静态回归测试 32 项全部通过。相较老版本，新版本主要解决了日期、语言、自然语言字段、多标的、K 线周期、并发、NER、错误响应、后端成功码变化及结果缺失值处理等一致性和稳定性问题。

## 3. 目录与契约结构变化

### 老版本

- 使用集中式 `references/tool-contracts.md` 保存全部工具契约。
- 指标字典集中在 `references/indicators.md`。
- 参数规范、校验规则、错误码分别散落在多个 JSON 和 Markdown 文件中。
- Agent 选择工具时需要跨多个文件读取和拼接规则，容易出现跨领域参数误用。

### 新版本

- 按 7 个 MCP server 拆分为：
  - `references/stock.md`
  - `references/fund.md`
  - `references/index.md`
  - `references/bond.md`
  - `references/financial-docs.md`
  - `references/economic.md`
  - `references/analytics.md`
- 股票、基金、指数的 `indexes` 字典直接内嵌到对应领域契约。
- 新增 `scripts/call-rules.json`，将公共参数规范化、冲突检测和后端字段映射集中管理。
- 工具清单迁移到 `scripts/tool-manifest.json`。

效果：从“全量集中契约、多文件交叉引用”变为“一次路由、只读一个领域契约”，降低上下文体积和错误引用概率。

## 4. 核心行为变化

| 对比项 | 老版本 | 新版本 | 改进效果 |
| --- | --- | --- | --- |
| 日期格式 | 公共参数要求 `yyyyMMdd` | 公共参数统一为 `yyyy-MM-dd`，CLI 再映射后端格式 | 用户侧格式一致，避免各工具日期格式混用 |
| 隐式日期 | 未形成统一禁止规则 | 禁止 `LAST`、昨天、今天等隐式日期；仅 Quote 工具保留契约允许的 `LAST` | 请求可复现，避免日期随执行时间漂移 |
| 自然语言字段 | `financial_docs` 使用 `query`，其它多用 `question` | 公共入口统一接受 `question`；文档工具保留 `query` 兼容，冲突时明确报错 | 降低调用方记忆成本，兼容旧调用 |
| 文档文本校验 | 曾对 `query` 施加全局无空格限制 | 仅校验为非空字符串 | 支持正常自然语言问题和带空格文本 |
| 语言参数 | 中文/English 与 CNS/ENS 并存 | 公共值统一为 `zh-CN` / `en-US`，CLI 映射后端编码 | 消除多套枚举 |
| 多标的 | 全局强制单标的，要求拆分调用 | 以具体工具契约为准；支持原生多代码的工具明确描述传法 | 不再错误限制后端已有批量能力 |
| K 线周期 | 存在数字型 `period` 魔法值 | 公共值使用语义化周期，数字编码仅在 CLI 内部映射 | 更易理解并避免填错 |
| 指标字段 | 独立大字典，调用时跨文件查找 | 指标内嵌领域契约并要求逐字复制 | 减少跨领域指标误用 |
| 并发 | 未形成明确的全局执行策略 | 默认串行；显式并发最大 10；超过 10 分批；首项探针成功后才扩散 | 避免本地或后端并发超限 |
| NER 错误 | 主要依赖文本型 `agent_action` | NER 和参数错误触发批次熔断，并要求用户提供标准名称或 Wind 代码 | 防止相同错误扩散到整批请求 |
| 参数冲突 | 缺少统一同义字段冲突处理 | 增加 `PARAM_CONFLICT_ERROR`，只修复被指出的冲突字段 | 避免静默覆盖参数 |
| 错误响应 | 以 `error.code`、`agent_action` 为主 | 结构化输出 `details`、`retry`、`circuit_breaker`、`correction` | 错误更容易被 Agent 稳定执行 |
| 后端状态码 | 容易把非 0 `data.code` 一律识别为错误 | 兼容 `0`、数值/字符串 `200` 及合法 2xx；未知状态但有数据时保留数据并告警 | 避免后端成功码变化导致误报和数据丢失 |
| 部分成功 | 返回体含 `error` 或未知状态时可能直接丢弃数据 | 有可用数据时输出 `UNKNOWN_BACKEND_STATUS_WITH_DATA` 或 `BACKEND_ERROR_WITH_DATA` 警告 | 返回体变化时优先保护有效数据 |
| 缺失值 | 缺少统一结果安全门禁 | `INVALID`、`null` 视为缺失，不得当 0 | 防止错误统计 |
| 完整性 | 可能依赖 `excelTotalCount` 判断总数 | 禁止依赖声明总数，只报告实际返回行数 | 避免伪造分页和排名完整性 |
| 行情解释 | 缺字段时存在自行推算风险 | 禁止用开收盘涨幅冒充日涨跌幅，单位不明不得推断 | 降低金融口径错误 |
| 临时参数文件 | 缺少唯一文件和清理规范 | 使用 `scripts/request-<唯一后缀>.json`，调用后删除并由 Git 忽略 | 避免并发覆盖及泄漏请求内容 |

## 7. 风险与建议

1. 新版本 CLI 明显更复杂，后续修改应持续补充单元回归，避免规则映射相互影响。
2. 当前 32 项属于静态和本地行为回归，不能替代 34 个真实 MCP 工具的端到端调用。
3. 新版本包含尚未提交的本地修改；提交前应确认报告对应的代码状态，并避免提交大体积真实调用 runlog。
4. 后端未来若再次修改成功码或包装层，建议坚持“已知错误优先、存在有效数据则保留并告警、原始响应可追溯”的兼容原则。

## 8. 最终评价

新版本结构更合理，参数口径更统一，对批量调用、错误恢复和后端协议漂移的容错能力明显强于老版本。现有本地回归全部通过，可以作为后续真实 34 工具回归测试的候选版本。
